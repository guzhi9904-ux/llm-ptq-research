# 中文编写与注释规范

## 基本要求

仓库内所有 Markdown 文档以中文为主。以下内容可以保留英文：

- 论文、算法、模型、数据集、会议和软件的正式名称。
- 命令、路径、类名、函数名和参数名。
- INT、FP、PTQ、RTN、GPTQ、PPL、KV cache、Hadamard、Hessian 等专业术语。
- 必须与官方实现保持一致的配置取值。

除上述内容外，标题、解释、步骤、注意事项、结论和表格说明均使用中文。

## 方法文档必须包含的中文说明

每个方法的 `README.md` 至少包含：

1. 中文概述：解决什么问题、属于哪条技术路线。
2. 核心逻辑：按真实代码调用顺序解释算法，不只翻译论文摘要。
3. 关键实现：列出入口文件、量化器、变换、校准和评测文件。
4. 核心实验：给出至少一条论文主设置的运行命令。
5. 参数说明：逐项解释关键参数的意义、默认值和影响。
6. 设置对照：并列列出论文值、官方代码默认值和本仓库复现值。
7. 结果说明：说明指标、数据集、模型、硬件以及结果证据等级。
8. 限制：指出 fake quant、真实 kernel、许可证和复现缺口。

## 命令注释示例

命令中的注释必须解释“为什么这样设置”，不能只重复参数名。

```bash
# 权重和激活均使用 4 bit；权重沿输入通道每 128 个元素共享量化参数。
# 校准使用 128 条样本，最后计算固定语料上的困惑度。
python main.py \
  --model meta-llama/Llama-2-7b-hf \
  --wbits 4 \
  --abits 4 \
  --group_size 128 \
  --nsamples 128 \
  --eval_ppl
```

为保证命令可直接执行，shell 命令不使用反斜杠后的行末注释；中文说明放在命令前或参数表中。

## 配置注释示例

```yaml
quantization:
  weight_bits: 4            # 权重量化位宽
  activation_bits: 4        # 激活量化位宽
  weight_group_size: 128    # 权重沿输入维分组；-1 表示 per-channel
  symmetric: false          # false 表示使用带 zero-point 的非对称量化

calibration:
  dataset: wikitext2        # 只用于校准，不与最终评测样本重叠
  split: train
  num_samples: 128
  sequence_length: 2048
  seed: 2
```

## 设置差异的写法

不得用一个“默认参数”覆盖所有来源，统一采用下表：

| 参数 | 论文设置 | 官方代码默认值 | 本仓库复现值 | 中文说明 |
|---|---:|---:|---:|---|
| `nsamples` | 128 | 128 | 待定 | 校准样本数，不是评测样本数 |
| `sequence_length` | 2048 | 2048 | 待定 | 校准序列长度 |
| `group_size` | 128 | `-1` | 待定 | `-1` 通常表示权重 per-channel |

## 代码内中文注释

- 本仓库新增的 adapter、runner、配置和实验代码必须有中文模块说明和关键逻辑注释。
- 第三方原始代码不批量翻译注释，以免制造难以审查的大型 diff。
- `upstream/` 中作者原始 README 保持原文；同级的本仓库方法卡和 `SOURCE.md` 提供中文说明。
- 对第三方代码的中文解释写入方法文档；必须修改时通过 `patches/` 保存最小补丁。
